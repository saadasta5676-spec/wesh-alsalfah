# تصور لوحة التحكم الشاملة — وش السالفة؟

> وثيقة تصميم ومراجعة فقط. لا تغيّر الواجهة الحية أو قاعدة البيانات أو صلاحيات Supabase.

## الهدف
تحويل لوحة الإدارة الحالية من شاشة لمراجعة المقالات إلى مركز إدارة عربي موحّد، RTL، متوافق مع الهوية الحالية (الأحمر/الأسود وخط IBM Plex Sans Arabic)، ويعمل على الجوال وسطح المكتب.

## هيكل التنقل المقترح

### 1) الرئيسية — نظرة عامة
- بطاقات: أخبار بانتظار المراجعة، منشورة اليوم، مسودات، ترندات نشطة.
- قائمة «يحتاج انتباهك»: أخبار قديمة في الانتظار، روابط/صور ناقصة، محتوى مجدول.
- اختصارات: خبر جديد، إضافة ترند، إضافة صفحة.
- لا تعرض أرقامًا وهمية؛ كل بطاقة مرتبطة ببيانات فعلية، وتظهر حالة «غير متاح» إذا لم يُبن مصدرها بعد.

### 2) الأخبار
- تبويبات: الكل، بانتظار المراجعة، مسودات، منشورة، مجدولة، مرفوضة.
- بحث بالعنوان، وتصفية بالقسم والمصدر والتاريخ والحالة.
- محرر الخبر: العنوان، slug، القسم، الكاتب، المصدر ورابطه، صورة رئيسية ونص بديل، ملخص، متن الخبر، كلمات مفتاحية، خبر مميز.
- إجراءات: حفظ مسودة، إرسال للمراجعة، نشر الآن، جدولة، إلغاء النشر، أرشفة.
- حقول مصدر الخبر ووقت النشر محفوظة مع سجل مراجعة؛ لا نسخ آلي لمحتوى محمي من RSS.

### 3) الترندات
- إدارة الوسوم الرائجة يدويًا: الاسم، slug، وصف مختصر، صورة اختيارية، ترتيب الظهور، نشط/موقوف، تاريخ بداية/نهاية.
- ربط الترند بأخبار موجودة، مع صفحة عامة لكل ترند.
- فصل «ترند تحريري» عن «عدد المشاهدات» حتى لا ندّعي شعبية غير مقاسة.

### 4) الأقسام والتصنيفات
- إنشاء وتعديل وإخفاء الأقسام: الاسم، slug، وصف، صورة، ترتيب، حالة النشر.
- منع حذف قسم مرتبط بأخبار؛ يطلب نقل الأخبار أولًا.
- تصنيفات فرعية اختيارية عند الحاجة، دون تعقيد مبكر.

### 5) الصفحة الرئيسية
- ترتيب وحدات الصفحة: عاجل، خبر رئيسي، أخبار مميزة، أحدث الأخبار، الترندات.
- تحديد عدد العناصر وترتيبها وفترة إبرازها.
- معاينة قبل الحفظ، وإمكانية استعادة ترتيب افتراضي.

### 6) الصفحات الثابتة
- محرر صفحات «من نحن»، «اتصل بنا»، «سياسة الخصوصية»، «الشروط»، «سياسة التصحيح».
- حالة مسودة/منشورة، عنوان SEO، وصف، slug، تاريخ آخر تحديث.
- صفحة سياسة الخصوصية ومعلومات الناشر يجب أن تكون واضحة قبل التقديم لـ AdSense.

### 7) SEO وبيانات الموقع
- اسم الموقع ووصفه، الشعار، روابط التواصل، البريد الرسمي.
- عنوان ووصف SEO افتراضيان، صورة مشاركة اجتماعية، إعدادات الفهرسة.
- أدوات تحرير slug وcanonical عند الحاجة؛ لا يسمح بإعداد noindex للموقع كله دون تنبيه واضح.
- sitemap وrobots تبقى ملفات/آليات نشر منفصلة عند تنفيذها.

### 8) المستخدمون والصلاحيات
- المدير: جميع الوظائف وإدارة الأدوار.
- المحرر: إنشاء وتحرير الأخبار والترندات بحسب ما يعتمد لاحقًا؛ لا يحذف نهائيًا ولا يدير المستخدمين.
- أي شاشة صلاحيات تعتمد على تحقق قاعدة البيانات (RLS)، وليس إخفاء الأزرار في JavaScript فقط.
- لا تُعرض مفاتيح service_role في المتصفح مطلقًا.

### 9) سجل النشاط
- من نفّذ الإجراء، نوعه، العنصر المتأثر، الوقت، والنتيجة.
- يسجل النشر والحذف وتعديل الأدوار وإعدادات الموقع.
- سجل append-only قدر الإمكان، ولا يتيح للمحرر العبث بسجلاته.

### 10) الإعلانات والربح — مرحلة لاحقة
- أماكن إعلانية محددة ومعاينة شكلها، تشغيل/إيقاف كل موضع.
- حقول معرفات الناشر/الوحدات تُضاف لاحقًا بعد اختيار الشبكة.
- لا تُدرج أكواد إعلانية فعلية قبل القبول والالتزام بالسياسات.

## تصور الواجهة
- شريط علوي: شعار، اسم المستخدم ودوره، رابط عرض الموقع، تسجيل خروج.
- قائمة جانبية RTL قابلة للطي، والعنصر النشط واضح.
- مساحة المحتوى: عنوان القسم + وصف + زر الإجراء الأساسي.
- بطاقات أرقام أعلى الصفحات، ثم جداول/قوائم مع بحث وفلاتر.
- نوافذ تحرير قصيرة أو صفحة تحرير كاملة للمحتوى الطويل.
- حالات موحدة: تحميل، فارغ، خطأ، نجاح، صلاحية غير كافية.
- على الجوال تتحول القائمة الجانبية إلى قائمة منسدلة/درج.

## ترتيب التنفيذ الآمن
1. تثبيت نموذج الأدوار ومراجعة SQL/RLS مع اختبار عدم فقدان وصول المدير الحالي.
2. إضافة هيكل التنقل والصفحات الفارغة دون توصيلها ببيانات غير موجودة.
3. تنفيذ إدارة المقالات المحسنة وربطها بالجدول الحالي.
4. إضافة جداول الترندات والأقسام وإعدادات الصفحة الرئيسية مع سياسات RLS مستقلة.
5. إضافة الصفحات الثابتة وSEO.
6. إضافة سجل النشاط وإدارة المستخدمين.
7. تجهيز الإعلانات لاحقًا.

## بيانات قاعدة البيانات المقترحة (ليست Migration)
- `profiles`: هوية المستخدم ودوره.
- `trends`: بيانات الترندات وترتيبها وحالتها.
- `categories`: الأقسام والـ slugs.
- `site_settings`: إعدادات عامة محددة ومتحقق منها.
- `pages`: الصفحات الثابتة ومحتواها وSEO.
- `homepage_sections`: ترتيب وحدات الصفحة الرئيسية.
- `audit_logs`: سجل نشاط غير قابل للتعديل من واجهة المحرر.
- لاحقًا `ad_slots`: تعريف مواضع الإعلانات دون أسرار.

## ما لا نفعله في هذه المرحلة
- لا ندمج طلب الصلاحيات الحالي ولا نشغّل SQL على Supabase.
- لا نغيّر ملفات الواجهة الحية ولا جدول articles.
- لا نضيف لوحة تحكم وهمية توحي بأن وظائف غير مربوطة تعمل.
- لا نضمن قبول AdSense؛ نبني المتطلبات التحريرية وتجربة الاستخدام وصفحات الثقة أولًا.
