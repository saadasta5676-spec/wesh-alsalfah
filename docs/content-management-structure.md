# هيكل إدارة المحتوى — وش السالفة؟

> مواصفة تنفيذية للوحة التحكم. هذه الوثيقة لا تنشئ جداول ولا تغيّر قاعدة البيانات أو الموقع المنشور.

## 1) شجرة الأقسام المعتمدة

  - قرارات وخدمات
  - اقتصاد ومشاريع
  - تعليم ووظائف
  - مجتمع وفعاليات
- العالم (world)
  - سياسة وعلاقات دولية
  - اقتصاد عالمي
  - أحداث عاجلة
  - علوم واكتشافات
- الترندات (trending)
  - ترند السعودية
  - ترند الخليج والعالم العربي
  - ترند عالمي
  - تحقق من المتداول
- التقنية والذكاء الاصطناعي (technology)
  - ذكاء اصطناعي
  - هواتف وأجهزة
  - تطبيقات ومنصات
  - أمن وخصوصية
  - شركات وتقنية
- الرياضة (sports)
  - الدوري السعودي
  - المنتخب السعودي
  - كرة القدم العالمية
  - انتقالات وبطولات
  - رياضات أخرى
- الترفيه والفن (entertainment)
  - أفلام ومسلسلات
  - مشاهير وفن
  - فعاليات وحفلات
  - ألعاب ومحتوى رقمي
- الاقتصاد والأعمال (business)
  - أسواق وشركات
  - استثمار ومشاريع
  - تجارة وريادة أعمال
  - أسعار وخدمات للمستهلك
- منوعات وحياة (lifestyle)
  - سفر وسياحة
  - طعام ومطاعم
  - صحة وتوعية عامة
  - قصص وتجارب
- وش السالفة؟ (explained)

«عاجل» ليست قسمًا موضوعيًا؛ هي وسم/حالة تحريرية تظهر فوق الخبر ويمكن أن ترتبط بأي قسم.

## 2) نموذج الخبر

### الحقول الموجودة حاليًا في public.articles
| الحقل | الاستخدام في المحرر |
|---|---|
| title | عنوان الخبر، مطلوب، حتى 180 حرفًا في الواجهة الحالية |
| category | القسم الرئيسي؛ تُستخدم أسماء الأقسام المتفق عليها |
| author | الكاتب/فريق التحرير |
| image_url | رابط الصورة الرئيسية |
| excerpt | ملخص قصير |
| body | نص الخبر |
| source_name | اسم المصدر |
| source_url | رابط المصدر |
| status | pending / draft / published / rejected |
| featured | إبراز الخبر في الصفحة الرئيسية |
| published_at | وقت النشر |
| created_at / updated_at | أوقات الإنشاء والتعديل |

لا توجد حاليًا أعمدة slug أو alt text أو tags أو scheduled_at أو reviewed_by. تبقى حقولًا مقترحة ولا يجوز للواجهة حفظها قبل اعتماد Migration وسياسات RLS.

### حقول واجهة المحرر المقترحة
- أساسي: العنوان، القسم، الكاتب، الملخص، متن الخبر.
- المصدر: اسم المصدر ورابطه، مع التحقق من صحة الرابط.
- الوسائط: رابط الصورة ونص بديل للصورة (النص البديل ينتظر دعم قاعدة البيانات).
- العرض: خبر مميز، عاجل (وسم منفصل مستقبلًا).
- النشر: مسودة، إرسال للمراجعة، نشر، رفض، أرشفة/إلغاء نشر.
- بيانات تحريرية مستقبلية: slug، كلمات مفتاحية، وصف SEO، وقت جدولة، ملاحظات المراجع.

## 3) دورة حياة الخبر
1. مسودة (draft): لا يراها الزوار.
2. بانتظار المراجعة (pending): ينتظر قرار المحرر/المدير.
3. منشور (published): يظهر للزوار بعد الاعتماد.
4. مرفوض (rejected): لا يظهر للزوار، مع سبب الرفض في سجل المراجعة مستقبلًا.
5. مؤرشف: حالة واجهة مقترحة؛ لا تستخدم قيمة status جديدة قبل اعتمادها في قاعدة البيانات.

أزرار المحرر المستقبلية: حفظ مسودة، إرسال للمراجعة، معاينة، نشر الآن، جدولة، رفض مع سبب، إلغاء النشر. لا تُفعّل أي عملية قبل ربطها بـRLS واختبارها.

## 4) قوائم إدارة الأخبار
- تبويبات الحالة: الكل، بانتظار المراجعة، المنشورة، المسودات، المرفوضة.
- البحث: العنوان، الملخص، اسم الكاتب، اسم المصدر.
- الفلاتر: القسم، الحالة، الكاتب، المصدر، مميز/عادي، الفترة الزمنية.
- أعمدة القائمة: العنوان، القسم، الكاتب، المصدر، الحالة، مميز، تاريخ الإنشاء/النشر، آخر تحديث.
- إجراءات الصف: معاينة، تعديل، إرسال للمراجعة، نشر/إلغاء نشر، حذف وفق الدور والسياسة.
- لا يعرض العداد إلا أعدادًا حقيقية من قاعدة البيانات؛ لا بيانات تجريبية أو أرقام افتراضية.

## 5) نموذج الترند

الترند كيان مستقل عن الخبر، ويمكن ربط عدة أخبار به. الحقول المقترحة:
- name: اسم الترند.
- slug: رابط مختصر فريد.
- summary: وصف محايد قصير.
- region: saudi / gulf / arab_world / global.
- platform: x / tiktok / instagram / youtube / search / other.
- source_url: رابط المنشور أو المصدر الأصلي.
- verification_status: unverified / checking / verified / debunked.
- starts_at و ends_at: فترة الصلاحية.
- status: draft / active / paused / expired.
- display_order: ترتيب العرض.
- image_url و image_alt: صورة اختيارية وبديلها.
- created_by و reviewed_by و created_at و updated_at: تدقيق ومتابعة.

لا نخزن «عدد تداول» أو «ترتيب عالمي» إلا إذا كان لدينا مصدر قياس موثوق وتاريخ تحديث واضح. لا يُستنتج أن الترند صحيح أو واسع الانتشار من عدد المشاركات وحده.

### قوائم الترندات
- الكل، مسودات، قيد التحقق، موثقة، نشطة، موقوفة، منتهية.
- فلاتر: المنطقة، المنصة، حالة التحقق، الفترة.
- أعمدة: الاسم، المنطقة، المنصة، التحقق، الحالة، بداية/نهاية، ترتيب الظهور.
- إجراءات: إضافة، تعديل، ربط أخبار، تفعيل/إيقاف، إنهاء، معاينة.
- وسم «غير متحقق» ظاهر بوضوح للترندات غير المؤكدة، ولا يظهر كحقيقة خبرية.

## 6) قوائم لوحة التحكم
1. نظرة عامة: أعداد الأخبار بحسب الحالة، الترندات النشطة، عناصر تحتاج مراجعة.
2. إدارة الأخبار: جدول الأخبار وفلاترها ومحررها.
3. الترندات: قوائم الترندات ومحررها وربط الأخبار.
4. الأقسام والتصنيفات: شجرة الأقسام، الترتيب، التفعيل؛ منع حذف قسم مستخدم قبل نقل محتواه.
5. الصفحة الرئيسية: ترتيب العاجل والخبر الرئيسي والمميز والترندات.
6. الصفحات الثابتة: من نحن، اتصل بنا، الخصوصية، الشروط، سياسة التصحيح.
7. الإعدادات وSEO: بيانات الموقع وبيانات المشاركة ومحركات البحث.
8. المستخدمون والصلاحيات: مدير ومحرر وفق صلاحيات قاعدة البيانات.
9. سجل النشاط: المنفذ، العملية، العنصر، التوقيت والنتيجة.
10. الإعلانات والربح: مرحلة لاحقة بعد تجهيز المحتوى والصفحات والقبول الإعلاني.

## 7) الصلاحيات المقترحة
- admin: إدارة الأقسام والإعدادات والمستخدمين، مراجعة ونشر وحذف المحتوى، وإدارة الترندات.
- editor: إنشاء وتعديل الأخبار والترندات وإرسالها للمراجعة؛ لا يدير الأدوار أو يحذف نهائيًا.
- public/anon: قراءة المحتوى المنشور فقط.
- إخفاء الأزرار ليس حماية؛ كل عملية يجب أن تفرضها RLS أو وظيفة موثوقة، مع اشتراط AAL2 لعمليات الفريق الحساسة بعد إكمال اختبار MFA.

## 8) نطاق التنفيذ الحالي
- اعتماد هذه الشجرة والحقول كمرجع تصميم.
- عرض وصف الهيكل في واجهة لوحة التحكم فقط.
- لا تغييرات على Supabase أو جدول articles أو سياسات RLS.
- لا عمليات حفظ/نشر/حذف وهمية، ولا ربط وظائف قبل اختبار MFA/AAL2.
- أي Migration مستقبلية تُراجع وتُختبر منفصلة، ولا تُطبق على المشروع الحي دون موافقة صريحة.
- العمل على draft/admin-role-security فقط؛ لا دمج PR ولا نشر للموقع الحي.
